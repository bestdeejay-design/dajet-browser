# Выбор направления стартового экрана

> Статус: решается по визуалу. Это карта пространства выбора, а не решение.
> Утверждено и не пересматривается: правило тишины, минимализм, локальность (канон продукта).

## Утверждённая база (общая для всех вариантов)

- Ноль сетевых запросов без действия пользователя; проверяемо монитором сети.
- Одна строка ввода по центру, подсказки только из локальной истории.
- Мгновенный рендер, offline неотличим от online.
- Темы и виджеты отложены за первой версией.

## Варианты

### A. Чёрный экран (Vision Arena)

Чёрный экран. Строка ввода. Всё. Браузер-пауза: стартовый экран ничего не содержит в принципе.

- Сильные стороны: предельно честная позиция, ничего не нужно объяснять; самый дешёвый в реализации; невозможно испортить.
- Риски: стартовый экран не несёт индивидуальности студии; «тишина» уже занята Search — отличать от апстрима будет сложнее.

### B. Галерея студии (изначальный канон)

Стильная тема + локальные виджеты (часы, календарь, батарея, «сейчас играет»); каждая тема — подписанная авторская работа.

- Сильные стороны: браузер = витрина студии; монетизация (бренд-темы); уникальность против апстрима.
- Риски: раздувание против принципа «ничего, что не попросил»; дольше делать.

### C. Дом с компаньоном (новое)

На стартовом экране живёт анимированный питомец: он не даёт Mac уснуть, а браузер не отвлекает от задач. Тихая, тёплая персона — лицо бренда, которого нет ни у кого.

- Сильные стороны: мгновенная эмоциональная узнаваемость; питомец — мем и маркетинг сами по себе; «не даёт спать компьютеру» — реальная утилитарная функция (caffeinate-обёртка).
- Риски: питомец может противоречить радикальному минимализму; анимация — расход батареи, нужна честная экономия.

## Возможные композиции

Варианты не взаимоисключающие:

1. **A по умолчанию + B/C как выбор.** Чистый экран у всех; галерея тем и питомец — opt-in в настройках. Минимализм не нарушен: по умолчанию — тишина.
2. **A + C (питомец как единственный обитатель).** Чёрный экран, строка и маленький компаньон. Если питомец получится живым — это самый запоминающийся вариант.
3. **Только A.** Жёсткая версия; B и C выносятся в будущее.

## Как решаем

1. Демо-филичист: [DEMOS.md](DEMOS.md) — каждый вариант показывается руками.
2. Питомец собирается в параллельной сессии (анимированный, WebGL/Canvas).
3. Решение по визуалу демо принимает владелец проекта.
